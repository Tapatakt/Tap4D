# Tap4D — План первой версии

## Концепция рендеринга

- Сцена четырёхмерная. Камера имеет позицию (Vector4) и произвольную ориентацию
  (4×4-матрица поворота); в системе координат камеры она смотрит вдоль оси **Z** (глубина).
- **Перспективная проекция** на трёхмерный «экран» (гиперплоскость Z = focal):
  точка (X, Y, Z, W) → (f·X/Z, f·Y/Z, f·W/Z).
- X и Y виртуального экрана → X и Y реального пикселя.
- W виртуального экрана (ана-ката) → цвет пикселя: градиент от красного (низ диапазона)
  до синего (верх диапазона). Цвет вычисляется **попиксельно** — по интерполированной W
  в точке пересечения луча с поверхностью, а не на весь объект.
- Зелёный канал зарезервирован под трёхмерные текстуры (в v1 — константа/отсутствует).
- Если на один реальный пиксель претендуют несколько точек поверхностей с разной глубиной —
  чередуем их по кадрам: кандидаты сортируются по глубине, на кадре N показывается
  (N mod count)-й.

## Примитивы сцены

- **Тетраэдр** (4 вершины Vector4) — базовый политоп; составные объекты (тессеракт и пр.)
  собираются из тетраэдров, как в 3D всё собирается из полигонов.
  Варианты: текстурированный (в v1 — просто видимый) и **заслонка** (не отображается,
  но участвует в отборе по глубине и скрывает объекты за собой).
- **Отрезок** (две вершины Vector4 + толщина) — рисуется линией заданной толщины,
  цвет — по интерполированной ана-ката вдоль отрезка.
- Сочетание заслонок и отрезков даёт «глухо чёрные» объекты с видимыми рёбрами.

## Алгоритм растеризации

1. Мировые координаты → система камеры (поворот + перенос).
2. Клиппинг тетраэдров плоскостью Z = near: пересекающиеся тетраэдры обрезаются
   и ретриангулируются (0–3 новых тетраэдра), полностью за плоскостью — отбрасываются.
3. Перспективное деление вершин на Z → тетраэдры в пространстве виртуального экрана.
4. Compute-шейдер, один поток на пиксель (x, y):
   - для каждого тетраэдра: попадает ли (x, y) в его XY-проекцию; если да — вычислить
     глубину Z и ана-ката W точки пересечения (интерполяция по барицентрическим
     координатам в исходном 4D-тетраэдре, чтобы цвет был перспективно корректным);
   - для каждого отрезка: расстояние от пикселя до проекции отрезка ≤ толщины —
     кандидат с интерполированными Z и W;
   - собрать кандидатов, отсортировать по глубине, выбрать по счётчику кадра,
     маппинг W → (red, blue), green из текстуры (v1 — константа).
5. Заслонки не отображаются и не занимают кадр чередования: список кандидатов пикселя
   обрезается на ближайшей заслонке — всё за ней скрыто на всех кадрах. Тело из
   тетраэдров-заслонок + отрезки-рёбра даёт проволочную модель с удалением скрытых линий.

В v1 — линейный обход всех примитивов на пиксель. Позже линейный обход заменяется
BSP-деревом для статичной геометрии за общим интерфейсом ускоряющей структуры;
контракт шейдера при этом не меняется.

## Структура решения

```
Tap4D.sln
Tap4D/                — основная библиотека
  Math/               — повороты 4D (6 плоскостей), преобразование в систему камеры,
                        перспективная проекция, клиппинг тетраэдров
  Geometry/           — Tetrahedron (4 × Vector4 + флаги видимости/заслонки),
                        Segment4 (2 × Vector4 + толщина), сборные политопы
  Scene/              — Scene, Camera4 (позиция + ориентация + focal),
                        маппинг ана-ката → цвет
  Rendering/          — ComputeSharp-шейдер, оркестрация GPU-буферов,
                        счётчик кадров чередования, интерфейс источника геометрии
                        (закладка под BSP)
Tap4D.Tests/          — xUnit: математика, клиппинг, проекции, маппинг цвета,
                        сверка GPU с CPU-эталоном
Tap4D.Viewer/         — WPF: WriteableBitmap + таймер кадров,
                        управление камерой (движение и повороты в 6 плоскостях)
```

## Этапы

1. Скелет решения: sln + три проекта, nullable, ComputeSharp.
2. Модуль `Math` + тесты: повороты (сохранение длины, ортогональность),
   переход в систему камеры, перспективная проекция известных точек,
   клиппинг тетраэдров плоскостью.
3. Модель геометрии и сцены + тесты: тетраэдры, отрезки, заслонки,
   фабрика тессеракта как эталонного объекта.
4. **CPU-референс-рендерер**: тот же алгоритм на процессоре, медленно, но даёт
   эталонные кадры для отладки математики и сверки GPU-версии.
5. ComputeSharp-шейдер + GPU-рендерер, сверка с CPU-эталоном в тестах.
6. Viewer: тессеракт + отрезки-рёбра, движение и вращение камеры с клавиатуры,
   автоматическое чередование кадров.
7. Закладка под будущее: интерфейс источника геометрии (сейчас плоский список,
   потом BSP), разделение статичных и динамичных объектов в сцене.

## Отложено на следующие версии

- Трёхмерные текстуры (зелёный канал).
- BSP-дерево для неподвижных политопов.
- Полноценный Z-buffer вместо чередования (если понадобится гибрид).
